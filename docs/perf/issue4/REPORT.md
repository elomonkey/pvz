# Issue #4 — освобождение ресурсов PersonRig

[Задача](https://github.com/elomonkey/pvz/issues/4). База: `main` после merge visual pass, `293bddc`. Рабочая ветка: `sol/4-person-rig-dispose`.

## Исправление и владение

`Client.destroy()` после удаления root из сцены и DOM-метки вызывает `rig.dispose()`. Существующая защита от повторного destroy сохранена; сам `PersonRig.dispose()` тоже идемпотентен.

`src/view/personResources.ts` освобождает только явно перечисленные в `PersonResources` ресурсы. Обхода всего дерева с автоматическим dispose нет: нельзя считать ресурс индивидуальным лишь потому, что на него ссылается персонаж. После освобождения списки очищаются.

| Освобождается | Остаётся общим |
|---|---|
| У обычного rig — собственные результаты merge для тела, рук, ног, головы, глаз и ручного аксессуара | Все геометрии из `cachedGeometry()` / `roundedBoxGeometry()`, включая готовые состояния бровей |
| У legacy/boss rig — результаты merge, включая глаза и объединённые прозрачные линзы; отдельная геометрия улыбки | `UNIT_BOX`, `UNIT_SPHERE`, `VERTEX_COLOR_MATERIAL`, материалы из `mat()` и `kitMaterial()` |
| Индивидуальный клон материала цвета посылки в руках | Геометрия коробки в руках, parcel-top decal с его материалом/текстурой, `PARCEL_VERTEX_MATERIAL` и кэш геометрий посылок мира |

Legacy-фабрика теперь также заполняет `body.userData.personResources`. Для прозрачного merge, возвращающего только число объединений, регистрируются новые Mesh, добавленные именно этим вызовом. Общие исходники merge туда не попадают. У общего rig использован уже существующий реестр владения.

Механика, графика, UI, экономика и `game.ts` не менялись. Сотрудник остаётся постоянным rig одной игровой сцены: restart не пересоздаёт его, и удалять его ресурсы при очистке клиентов нельзя.

## Long-session: production preview, 20 циклов

Воспроизведение:

```bash
npx playwright install chromium
npm run build
npm run perf:long-session -- --label current --check-plateau
```

Команда сама поднимает **production preview** на `127.0.0.1:4177` (порт должен быть свободен), открывает свежий Chromium context и сохраняет JSON/финальный кадр в `test-results/long-session/current/`. Запускать отдельно от e2e/perf. После исходной сборки до исправления для baseline выполнялась та же команда без `--check-plateau`; проверка плато на baseline ожидаемо выявляет рост геометрий.

Методика:

- Chromium 158.0.8127.18, 960×720, DPR 1, seed 73129, без сохранённой игры; обучение отключено.
- 20 настоящих циклов `startNewGame()` → четыре фиксированных student/mom с посылками → `restartGame()` → два стандартных клиента меню. Создание и удаление проходят через обычные методы Game/Client, fixture не освобождает их вручную.
- В каждом состоянии: два RAF для стабилизации, затем 12 RAF-интервалов; записываются avg/p95/max frame time, `renderer.info.memory.geometries`, textures, programs, материалы и DOM-метки.
- Обслуживание приостановлено через существующий console API, мир/UI и рендер продолжают обновляться. Это повторяемая нагрузка жизненного цикла, а не полное прохождение волн.
- Первые четыре цикла допускаются для прогрева. `--check-plateau` требует **полного постоянства** всех шести счётчиков в циклах 5–20 отдельно для активной сцены и меню. После исправления они постоянны уже с первого цикла.

### Счётчики: цикл 1 → цикл 20

| Состояние | Версия | Geometries | Textures | Programs | Материалы без dispose¹ | DOM-метки |
|---|---|---:|---:|---:|---:|---:|
| 4 клиента с посылками | До | 127 → 1058 | 17 → 17 | 9 → 9 | 70 → 184 | 4 → 4 |
| 4 клиента с посылками | После | **110 → 110** | 17 → 17 | 9 → 9 | **68 → 68** | 4 → 4 |
| Меню, 2 клиента | До | 144 → 1075 | 17 → 17 | 9 → 9 | 72 → 186 | 2 → 2 |
| Меню, 2 клиента | После | **95 → 95** | 17 → 17 | 9 → 9 | **66 → 66** | 2 → 2 |

До исправления добавлялось ровно 49 загруженных геометрий за полный цикл. После исправления рост отсутствует. Счётчики не обязаны падать до нуля: комната, сотрудник и общие кэши остаются живыми.

¹ В Three.js нет `renderer.info.memory.materials`. Fixture учитывает UUID замеченных в сцене материалов и события `dispose`, включая скрытые меши. Хранятся UUID, а не ссылки на удалённых персонажей/материалы. Это счётчик объектов без сигнала освобождения, а не оценка байтов GPU или JS heap. Дополнительно измеряются материалы, на которые прямо ссылается текущая сцена: 68 в активной сцене и 66 в меню, стабильно до/после. В production этот диагностический учёт не добавлялся.

В этом коротком контрольном прогоне устойчивого роста frame time нет ни до, ни после; исправление подтверждено счётчиками ресурсов, а не обещанием роста FPS. Используется **SwiftShader**, программный GPU. Это не мобильный FPS, не длительный real-time soak и не доказательство, что устранена единственная причина всех описанных владельцем лагов. 12 отсчётов на состояние достаточно для сопутствующей диагностики, но мало для статистически надёжных хвостовых перцентилей. Время кадра не является жёстким CI-порогом из-за шума окружения.

## Регрессии и обычный perf

- `npm run build` — проходит; прежнее предупреждение о размере bundle остаётся.
- `npm test` — **43/43**, включая два новых теста idempotence, независимого владения и сохранности общих геометрии/материала/текстуры.
- `npm run test:e2e` — **5/5**. Основной цикл, visual/office budget и два новых lifecycle-сценария.
- E2E long-session повторяет **20 циклов** на dev Vite, с 4 RAF-отсчётами на состояние для скорости CI. JSON прикладывается к результату теста. Используются те же fixture и проверка плато, что в production runner.
- Второй lifecycle e2e трижды создаёт/отрисовывает/удаляет все **11 типов**: шесть обычных + Галя, баба Зина, Саня, королева примерок и Валера. Проверяются idle/impatient/angry, перенос, двойной destroy и дополнительный прямой dispose, удаление меток, ровно одно освобождение каждого собственного ресурса и отсутствие dispose общих ресурсов. После прогрева счётчики geometry/textures/programs повторяются. Два клиента меню продолжают отображаться.
- `npm run perf -- --label issue4-after --check-budget` — проходит: свежие сцены сохранили **122 / 173 draw calls**, **60 615 / 83 430 triangles**, **16 / 19 textures**, **9 / 9 programs**. avg/p95/max: **109.05/116.80/133.30** и **121.42/133.40/133.40 мс**. Карты теней отключены, refresh 0 мс. [Raw](fresh-scenes.json).
- `console.error` / `pageerror` отсутствуют в production long-session, e2e и обычном perf. Прежнее предупреждение `THREE.Clock` остаётся.
