# AGENTS.md — правила работы AI-агентов

## Роли

- **OpenCode Lead** — главный по проекту: архитектура, приоритеты, декомпозиция задач, ревью, финальное техническое решение и координация следующего шага.
- **Codex Sol** — исполнитель: берёт только назначенную задачу, работает в отдельной ветке, не меняет архитектуру без согласования, открывает PR и останавливается до ревью.
- **Владелец репозитория (человек)** — доступы, секреты, GitHub-настройки и финальное одобрение/merge, если включена защита ветки.

Правило иерархии: **OpenCode Lead ставит задачу и принимает результат. Codex Sol не начинает новую задачу самостоятельно и не merge-ит PR.**

## Источник истины

- Задачи и их статус — **GitHub Issues**, а не переписка в чате.
- Долгосрочный план — `docs/ROADMAP_ARCHITECTURE_GRAPHICS.md`.
- Текущее состояние и правила игры — `README.md` и `docs/GAME_GUIDE.md`.
- Ветка `main` защищена: только через PR, без прямых push и force-push.

## Режим работы

- В один момент времени активна **одна задача**.
- Один PR = одна задача. Нельзя смешивать рефакторинг, новую механику и косметику.
- Перед работой: `git fetch origin`, переключиться на `main`, `git pull --ff-only`.
- Ветка:
  - Lead: `lead/<short-slug>`
  - Sol: `sol/<issue-number>-<short-slug>`
- Если два агента работают одновременно, они используют **разные worktree или разные клоны**, а не один рабочий каталог.
- Никаких прямых коммитов в `main`.

## Обязательный цикл задачи

1. Lead создаёт issue с целью, границами, критериями готовности и способом проверки.
2. Sol переводит issue в `status:in-progress`, создаёт ветку от свежего `main`.
3. Sol делает минимальные изменения, запускает `npm run build` и `npm test`.
4. Для UI-изменений Sol дополнительно проходит браузерный сценарий и фиксирует результат в PR.
5. Sol коммитит, push-ит ветку и открывает PR по шаблону.
6. Sol переводит issue в `status:review` и **останавливается**.
7. Lead проверяет diff, запускает проверки, оставляет замечания.
8. Если нужны правки — Sol исправляет только замечания в той же ветке.
9. После одобрения PR сливается в `main`, issue закрывается, Lead формулирует следующую задачу.

## Definition of Done

- `npm run build` проходит.
- `npm test` проходит.
- Новые правила покрыты unit-тестами.
- Для UI/сцены — браузерный смоук без ошибок в консоли.
- Обновлены README/roadmap/документация, если изменились структура, тесты или поведение.
- В PR есть: ссылка на issue, список изменений, результаты проверок, риски и что смотреть ревьюеру.

## Запрещено

- Пушить в `main` напрямую.
- Делать force-push в общие ветки.
- Менять архитектуру или публичные контракты без согласования с Lead.
- Оставлять в PR секреты, токены, `.env`, `node_modules`, `dist`.
- Начинать следующую задачу до закрытия текущей.

## Codex Sol: стартовый промпт

```text
Ты Codex Sol, исполнитель в проекте PVZ Tycoon.
Прочитай AGENTS.md, docs/AGENT_WORKFLOW.md и issue #<номер>.
Работай только по этой задаче, в отдельной ветке sol/<номер>-<slug> от main.
Не меняй архитектуру без согласования. Не пушь в main, не merge-и PR.
Сделай минимальные изменения, запусти npm run build и npm test.
Для UI-изменений пройди браузерный смоук.
Открой PR по шаблону, заполни отчёт и остановись до ревью OpenCode Lead.
```
